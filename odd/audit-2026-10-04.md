# Internal audit — HVE, 2026-10-04

**Branch**: `hve2-visual-rewrite` · **Version**: 1.0.0 · **Scope**: the whole repository, read-only.
**Method**: static measurement plus targeted reading. Nothing was modified to produce this report.

## What this audit could NOT check (state these before reading any conclusion)

- **`cargo-audit` is not installed**, so no RustSec advisory was verified. Nothing here
  claims a dependency is safe or unsafe, only that some are old.
- **`shellcheck` is not installed**, so the shell scripts were read, not linted.
- **No live Hyprland interaction and no profiler**: runtime behaviour claims come from
  the test suite and from reading code, not from running the app against the compositor.
- Counts are static: a `contains()` count is not proof that each one is weak, and an
  unreferenced file is not proof it is useless.

## BLOCKERS for publishing

1. **`LICENSE` file does not exist** while `Cargo.toml` declares `license = "MIT"`. A
   published MIT project with no license text is legally ambiguous, and packaging tools
   expect the file.
2. **`hve.desktop` hardcodes one machine's home directory**:
   `Exec=/home/ximo/.local/bin/hve`. It cannot work for any other user, which makes it a
   publication defect rather than a personal one. `Exec=hve` (the installer already
   offers a `/usr/local/bin` symlink) or a `sh -c` wrapper resolves it.
3. **No git remote is configured** (`git remote -v` is empty). Nothing can be published
   in this state; the branch exists only locally.
4. **`README.md` and `WIKI.md` have drifted apart** (32 114 B vs 33 082 B) while the
   README's own maintenance note states they are kept identical and must be edited
   together. The stated invariant is already broken.
5. **`Cargo.toml` lacks `repository` and `readme`**, both expected by crates.io-style
   publication. `description`, `license`, `authors` and `version` are present.

## HIGH

6. **An unresolved forced close.** The keeper hit it twice while adjusting animation
   curves with the keyboard; it has not reproduced since. Nothing in this audit
   identified the cause. What IS known: the app hid itself is ruled out (auto-minimize is
   off in the keeper's config), the curve preview component is pure arithmetic, the Rust
   handlers on that path do not index lists or exit, and all 39 Motion tests — including
   the full keyboard walk — pass headlessly, so the trigger needs the live environment.
   A captured log will discriminate between a Rust panic and an external kill.
   **Adjacent fragility found while looking**: the theme-transition statics are locked
   with bare `THEME_*.lock().unwrap()`. One panic while holding one of those locks poisons
   it, and every later access panics in turn — turning a single fault into an immediate
   cascade with no useful message.
7. **A systemic test-quality pattern that hides real defects.** In
   `src/shell/ui_tests.rs`: **51 tests read repository source files** and assert on their
   text, and the file contains **241 `contains(` assertions**. Those tests pass when the
   behaviour breaks — it happened twice in one day: a row guard that kept passing after a
   row could be deleted, and a preset-style validator whose table was written beside the
   generator and encoded the same wrong assumption (that one hid a live Hyprland
   rejection). The pattern, not the individual tests, is the finding.

## MEDIUM

8. **Dead code left by the removed old UI.**
   - **76 i18n keys are used by no code path**: `welcome` 21, `home` 18, `settings` 11,
     `themes` 9, `panel` 6, `meta` 3, `animations` 2, `borders` 2, `shaders` 2,
     `widget` 2. (An earlier estimate of ~109 was made with a cruder method; 76 is the
     measured number.)
   - **Two `.slint` components are referenced by no other file**:
     `ui/gallery/HexDelegate.slint` (5 818 B) and `ui/panel/PickTuneBlock.slint` (1 301 B).
   - `ui/gallery/FilterBar.slint` is instantiated by nothing (the HVE 2 rewrite replaced
     it), yet it still carries 15 freshly-bound labels and a compatibility property.
   - Smaller leftovers: `SystemSection`'s `settings-title` property (nothing reads it),
     `ui/shell.slint`'s `Auto-minimize` / `Timer:` defaults (always overridden), and four
     keys added during the System slice that no surface can reach.
9. **One old transitive dependency chain.** `ksni` (the tray) pulls `dbus-codegen`,
   which pulls **`clap 2.34`** and **`bitflags 1.3.2`** — both 2020-era, build-time only.
   `anstyle` is duplicated between `clap 4.6` and `i-slint-compiler`. With no
   `cargo-audit` installed this is a maintenance smell, not a verified vulnerability.
10. **Clippy debt, and clippy is available.** 54 × "struct update has no effect, all the
    fields in the struct have already been specified", 15 × negated comparison on
    partially ordered types, 11 × needless borrow, 9 × needless `to_string`, 9 × cast to
    the same type, 6 × `clone` on a `Copy` type, 6 × **redundant redefinition of the
    `guard_permits` binding**, 5 × `assert_eq!` with a literal bool, 4 × manual
    `div_ceil`. None is a bug; together they are a cheap CI gate that is currently open.
11. **`install.sh` supports six distros and only one is exercised.** The detection and
    package-install branches cover pacman, apt, dnf, zypper, xbps and emerge; only the
    Arch-family path has ever run. The script is otherwise careful: `set -euo pipefail`,
    refuses to run as root, installs under `$HOME`, bilingual messages.

## GOVERNANCE / PROCESS

12. **The "sealed engine" rule has been crossed repeatedly.** The HVE 2 skill states that
    `engine.rs`, `config.rs`, `settings.rs`, `theme_manager.rs`, `app_state.rs`,
    `watcher.rs` and `utils.rs` are reused, never rewritten. Commit counts touching them:
    `theme_manager` 20, `config` 17, `watcher` 13, `settings` 11, `engine` 7,
    `app_state` 4, `utils` 3. This audit itself added a field to `config.rs` today. Either
    the rule is aspirational and should say so, or the boundary needs restating.
13. **The UI test suite is one 18 199-line file** holding 225 tests. It is the single
    largest artifact in the repository and the first place a newcomer must look.
14. **A process finding about this line of work.** Building the i18n inventory for the
    translation slices, the static method was wrong **eight times** — it missed override
    chains (an instance overriding a component's defaults), missed an entire host file
    (the gallery drawers), and produced false positives by not accounting for setter
    prefixes. What corrected it every time was the render read with eyes, not the grep.
    Any future "find every X" task here should be planned with a behavioural check as the
    primary evidence and the static scan as a hint.

## Suggested order, if this is picked up

1. The five publication blockers — they are small, and three of them are one-line fixes.
2. Decide about the forced close: keep the log capture ready; it is the only path to a
   cause, and the poisoned-lock cascade makes any single fault worse than it looks.
3. Convert the source-text assertions into binding or behaviour assertions where they
   guard something that matters, starting with the two that failed today.
4. Dead-code sweep as its own change, with the counts above as the checklist.
5. Make `cargo clippy` and a license/README check part of whatever runs before a release.
